## ทำไม `machine.py` ถึงถูกปลดระวาง ไม่ใช่แก้

`machine.py` เป็นบรรพบุรุษของสาย `AD Log Data*` — parse ข้อมูลแบบเดียวกันแต่แย่กว่าทุกด้าน
และมีบั๊ก 2 จุดที่ทำให้ข้อมูลใน `inadatabase.ad_log3` เสียหายแบบไม่มีร่องรอย:

1. **`mc = 8` hardcode** (บรรทัด ~20) — ทุกแถวที่สคริปต์นี้เขียนจะมี `machine = '8'`
   แทนที่จะเป็นชื่อเครื่องจริงจาก `item.Machine`
2. **`except: pass`** ที่ insert ทุกแถว — error ทุกชนิดถูกกลืนหมด ไม่มี log ไม่มีเสียงเตือน

`AD Log DataV4.py` ทำงานแทนได้ครบและดีกว่า (มี logging, timeout, retry, คอลัมน์ alarm/Status/LotName
ที่ `machine.py` ไม่มีเลย) จึงเลือกปลดระวางแทนการแก้ เพื่อไม่ให้เหลือ pipeline ที่รันแล้วทำข้อมูลเพี้ยนได้อีก

**ตรวจข้อมูลเก่าที่อาจเสียไปแล้ว:**
```sql
SELECT COUNT(*) FROM inadatabase.ad_log3 WHERE machine = '8';
```
ถ้าเจอแถวแบบนี้ คือร่องรอยของ `machine.py` ที่เคยถูกรัน — ต้องตัดสินใจว่าจะลบหรือ map กลับเป็นเครื่องจริง
(map กลับได้ยาก เพราะข้อมูลต้นทางว่าเป็นเครื่องไหนถูกทับไปแล้ว)
